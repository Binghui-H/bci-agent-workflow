# BCI Agent Workflow 项目规则

所有 agent 必须使用中文汇报。

## 工作原则

| 原则 | 要求 |
|---|---|
| 共享文档优先 | 关键事实必须写入 `.agent-workflow/`，不能只留在聊天里 |
| 阶段门禁优先 | 未通过设计、审阅或验证门禁，不得进入下一阶段 |
| 主会话授权 | 只有 orchestrator 可以推进 RUN_STATE，角色间通知不能直接授权下一阶段 |
| 单写者 | 只有 RUN_STATE.md 指定的当前写入角色可以修改代码或 workflow 产物 |
| 事件留痕 | 每次设计完成、实现交付、返修、复审和验证都必须追加 EVENT_LOG.md |
| 最小改动 | 执行 agent 只修改当前阶段允许范围内的文件 |
| 领域契约优先 | 脑机信号的采样率、通道顺序、shape、窗口、延迟、标签语义必须明确 |
| 测试证据优先 | 报告“通过”前必须说明实际运行了哪些测试和结果 |

## 默认角色权限

| 角色 | 是否允许改代码 | 说明 |
|---|---:|---|
| 设计 agent | 否 | 写 TASK / DESIGN / PHASE_PLAN |
| 执行 agent | 是 | 只做当前阶段实现和测试 |
| 审阅 agent | 默认否 | 只写 REVIEW_LOG 和返修意见 |
| 验证 agent | 否 | 只读验证并写 VALIDATION_REPORT |

## 强制停止条件

| 条件 | 处理 |
|---|---|
| 设计存在阻塞澄清项 | 停止，交给主对话问用户 |
| P0/P1 review issue 未关闭 | 不得进入下一阶段 |
| 测试无法真实运行 | 不得声称通过 |
| 实现偏离 DESIGN.md | 返修或更新设计并重新确认 |
| 需要破坏性操作 | 等用户确认 |
